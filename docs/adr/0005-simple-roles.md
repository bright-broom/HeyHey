# ADR 0005：役割は「管理者」と「会員」の 2 つ ＋ ルール 1 つ

- 日付：2026-09-27
- 状態：採用

## 背景

役割がサイトに 3 つ（オーナー・管理者・会員）、グループに 3 つ（オーナー・モデレーター・メンバー）あり、
「オーナー」が 2 つの意味で出てくるなど、使う人も運営する人も混乱していた。

## 決定

権限を「役割」と「持ち主」の 2 つの軸に分け、人が覚えることを最小にする。

1. **役割は 2 つ**：会員と管理者。管理者は会員のすべてに加えて、コミュニティ全体を管理できる
2. **ルールは 1 つ**：作ったもの（投稿・コメント・イベント・グループ）は、作った人が管理する。
   グループの持ち主は「代表」と呼び、交代できる（DB の値は group_members.role = owner のまま）

| 変更 | 置き換え |
| --- | --- |
| サイトのオーナーを廃止し、管理者にまとめる | 管理者どうしは対等。管理者に関わる変更（任命・解任・停止）は、ほかの管理者全員に通知して監査ログに残す。互いの操作が見えることで、1 人への権限集中を防ぐ |
| オーナー権限の移譲（パスワード＋コード）を廃止 | 移譲する相手がいないので不要 |
| 「オーナーは退会できない」を廃止 | 最後の 1 人の管理者は退会・解任・停止できない。管理者の変更は DB のロックで 1 つずつ行い、同時に停止し合って 0 人になるのを防ぐ |
| グループのモデレーターを廃止 | 代表が承認・除外・設定・閉じる・交代を行う |

## 移行

- マイグレーション 0013：グループのモデレーターをメンバーに戻す
- マイグレーション 0014：サイトのオーナーを管理者にする
- 最初の管理者を作るシードの環境変数（OWNER_EMAIL など）は、デプロイの設定を壊さないよう名前をそのままにした

## 捨てたもの

- 「最終責任者が 1 人いる」ことによる強い抑止。代わりに、全管理者への通知と監査ログで見える化する。
  悪意のある管理者が 1 人いても、ほかの管理者はすぐ気づき、その人を解任・停止できる
