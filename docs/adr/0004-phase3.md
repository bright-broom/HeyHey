# ADR 0004：Phase 3 の機能（検索・動画とファイル・メッセージ・イベント・アプリ化）

- 日付：2026-09-27
- 状態：採用

## 背景

要件定義書の Could 機能（F-08 全文検索、F-13 動画・ファイル添付、F-16 1 対 1 メッセージ、F-17 イベント、アプリ化）を実装する。
どれも「承認された人以外には何も見えないこと」を崩さない形で入れる。
あわせて、Phase 2 までで見落としていた本番の制約（Vercel Functions のリクエスト本文は 4.5MB まで）に対応する。

## 決定

| 項目 | 採用 | 理由 |
| --- | --- | --- |
| 画像の送信 | ブラウザで長辺 2048px の JPEG に縮めてから送る。合計 4MB を超えたら送らせない | 本番は 1 回の送信が 4.5MB まで。スマホの写真 2〜3 枚で投稿できなくなっていた。位置情報はサーバーの sharp で必ず落とす（縮めるのは量を減らすためだけ） |
| 検索の方式 | 本文の部分一致（NFKC で正規化、空白区切りは AND）。全文索引は使わない | 日本語は PostgreSQL の標準の全文検索で単語に区切れない。会員 1,000 人規模なら部分一致で足りる |
| 検索の範囲 | フィードと同じ `visiblePost` を通す。メンションの記法（`@[名前](u:ID)`）は検索の対象から外す | 記法には書いた時点の名前が残るので、いま見えない相手の昔の名前で投稿を探せてしまう |
| 動画・ファイルの送り方 | ブラウザから一時置き場（`staging/<自分の会員ID>/…`）へ直接上げ、投稿するときにサーバーが確かめて本置き場へ移す。本番は Vercel Blob の client upload、ローカルは `PUT /api/uploads/local` | 4.5MB を超えるファイルをアプリの関数を通さずに上げるため。上げる許可は「自分の一時置き場のそのキー・その種類の Content-Type・その種類の上限サイズ」に限る |
| 添付を確かめる内容 | 持ち主（キーの会員 ID）、大きさ、先頭のバイト列（mp4/mov は `ftyp`、PDF は `%PDF-`、Office は zip の中身）。拡張子と Content-Type は信用しない | 偽装したファイル（PDF を名乗る HTML など）を配らない |
| 動画のメタデータ | `udta` / `meta` / `uuid` / `XMP_` の箱を中身ごと消し、映像・音声以外のトラック（GPS など）は mdat の中のデータごと消す。作成日時も 0 にする。fragmented MP4 と読めない動画は受け付けない | 撮影場所は箱にもトラックにも入る。箱の大きさと位置を変えないので、再生に必要なオフセットは壊れない |
| 添付の種類と上限 | 動画（MP4 / MOV）50MB、ファイル（PDF・Word・Excel・PowerPoint）20MB。1 投稿 2 件まで | 容量と悪用の余地を小さく。HTML・SVG など、ブラウザで動くものは受け付けない |
| 添付の配信 | 画像と動画はページ内で表示、ファイルは必ずダウンロード（`Content-Disposition: attachment`）。動画は範囲指定（206）に対応 | ファイルをアプリのドメインで開かせない。Safari の動画再生は範囲指定が必須 |
| 使われなかった一時置き場 | 投稿していない添付は 1 人 4 件まで。1 時間たったものは次に上げるときに消し、定期処理でも 2 時間で消す | 上げたまま投稿しなかった分で容量を使い潰させない |
| メッセージを送れる相手 | 承認済みの会員どうし（規約に同意済み）。ブロック関係の相手とのやりとりは存在しないのと同じ | 友達だけに絞るより使いやすく、嫌な相手はブロックで止められる |
| メッセージの本文 | 当事者の 2 人にだけ見せる。管理者にも見せない。通報は相手の会員に対して行う | 管理者が私信を読めると、場の信頼が崩れる |
| メッセージの通知 | 未読がない状態で届いた最初の 1 通だけ（メールでも知らせる） | 1 通ごとに知らせると多すぎる |
| 退会したときのメッセージ | 「削除」を選んだ人の送信分は本文ごと消す。相手の画面には「削除されたメッセージ」 | 投稿・コメントの扱いと合わせる |
| イベントの見える範囲 | 投稿と同じ考え方を `visibleEvent` の 1 か所で判定（全会員／グループのメンバー、作った人とのブロック、停止中の作成者） | 一覧・詳細・出欠・参加者の一覧・通知のすべてに同じ判定を効かせる |
| イベントの運営 | 管理者は理由を付けて非表示にできる（監査ログに残る）。作った人は中止・削除できる。中止すると参加・未定の人に知らせる | イベントは通報の対象外なので、運営が止める手段を別に持つ |
| アプリ化 | Web アプリのマニフェストとアイコンだけ（ホーム画面に追加できる）。Service Worker は置かない | ネイティブアプリより早く出せる。オフラインのキャッシュは非公開の中身を端末に残すので入れない |

## 検証

- 単体・結合テスト：検索（見えない投稿・メンションの記法・ワイルドカード）、添付（他人の一時置き場・偽装・メタデータ・配信の範囲）、メッセージ（当事者以外・ブロック・停止・退会・書き出し）、イベント（グループ・ブロック・中止・管理者の非表示）
- E2E：検索、プロフィールからのメッセージ、イベントの出欠と通知、ファイルを添付した投稿とダウンロード
- 独立したエージェントによるセキュリティレビュー：高 0・中 3・低 8 件。すべて修正し、回帰テスト（tests/unit/review-phase3.test.ts）を足した
  - 中：動画の GPS トラックと撮影日時が残る → トラックのデータを mdat から消し、日時も消す。fragmented MP4 は受け付けない
  - 中：一時置き場で容量を使い潰せる → 投稿していない添付は 4 件まで、1 時間で消す
  - 中：大きな動画でメモリを 2 重に使う → その場で書き換える
  - 低：出欠の値の検査、会員 ID の大文字、管理者の非表示もグループの範囲に従う、抜けた人を参加者に出さない、ファイル名の書字方向の文字、検索の回数制限、ローカルの上げ口の大きさの確認
  - 確認事項：Blob のストアは private。直接アップロードの許可はパス・種類・大きさに限り、上書きを許さない

## 未対応（次の候補）

- メッセージの即時配信（いまは開いている間 15 秒ごとに取り直す）
- 動画の変換（形式・画質をそろえる）。いまは受け取った形式のまま配る
- 検索の全文索引（投稿が数十万件を超えたら pg_bigm などを検討）
