# ADR 0003：Phase 2 の機能（ブロック・メンション・メール通知・グループ）

- 日付：2026-09-27
- 状態：採用

## 背景

Phase 2 の完了条件は「週次アクティブ率 40%」。
人を呼び戻す機能（メール通知・メンション・グループ）を足すほど、情報が意図しない相手に届く経路も増える。
どの機能も「承認されたメンバー以外には何も見えないこと」を崩さない形で入れる。

## 決定

| 機能 | 採用 | 理由 |
| --- | --- | --- |
| 入れる順番 | ブロック → メンション → メール通知 → グループ | 安全の仕組みを先に入れ、後の機能がそれを前提にできるように |
| ブロック | 双方向。判定は `visiblePost` / `visibleComment` に足す | 1 か所に足せば、フィード・詳細・画像・コメント・通報・通知・メンション・タグのすべてに効く |
| ブロックされた側から見た相手 | 存在しないのと同じ（404・「見つからない」） | 通報・友達申請・ブロックし返しなど、どの操作の応答からもブロックを推測させない |
| ミュート | 一方向。ホームのフィードと通知からだけ外す | 相手に伝わらず、プロフィールを開けば見える、という軽い手段として |
| 運営の通知 | 管理者個人のブロック・ミュートでは止めない | 審査・通報対応が漏れないように |
| メンションの書き方 | `@[名前](u:会員ID)`。入力欄で候補から選ぶ | 表示名は重複・空白がありうるので、名前では相手が確定しない |
| メンションの入力欄 | 見せるのは `@名前` だけ。どこがメンションかは位置で持ち、送るときに記法へ戻す。中を書き換えたらただの文字 | 記法を見せない。同名の別人も位置で区別でき、書き換えで別人を指すこともない。JS が動く前は記法のまま送る |
| メンションの表示 | 表示前にサーバー側で現在の名前を引き直す。見えない相手は「@メンバー」 | 書いた名前を信用しない（なりすまし防止）。見えない相手の名前・ID をブラウザに送らない |
| メンションの通知 | その投稿（コメントならそのコメント）を見られる人にだけ | 通知の有無から、見えない投稿ややりとりの存在を知らせない |
| メールの中身 | 件数とリンクだけ。投稿の中身も人の名前も書かない | メールは外部のサーバーに残り、転送もされる |
| メールの送り方 | 応答の後（`after()`）に送る。同じ人には 15 分に 1 通まで。送れたときだけ「送った印」 | 元の操作を遅らせず、失敗で巻き戻さない。送れなかった分は定期処理が送り直す |
| 週 1 回のまとめ | 月曜の定期処理（取りこぼしは水曜まで）。同じ人には 6 日に 1 通まで | Hobby プランの Cron は 1 日 1 回のため |
| グループの種類 | 参加自由と承認制。どちらも投稿はメンバーにだけ見える | 名前と説明は全会員に見せて見つけられるようにし、中身は閉じる。違いは入り方だけ |
| グループの判定 | `visiblePost` に「グループの投稿ならアクティブなメンバー」を足す | ブロックと同じく、1 か所で全経路に効かせる |
| 週次アクティブ率の推移 | 毎日の定期処理で、人数だけを 1 日 1 行残す（activity_snapshots）。管理画面に週ごとの推移と目標 40% の達成を出す | Phase 3 に進む条件の数字。最終アクセス日時は上書きされるので、記録しないと過去の週が残らない。本番に出した初日から取る必要がある |
| グループの役割 | 廃止。作った人（代表）が管理する（2026-09-27、ADR 0005） | 役割が多く混乱したため |
| グループを閉じる | 削除ではなく「閉じる」（誰にも見えなくする）。オーナーとサイトの管理者 | 運営上の対応と、やり直しの両方ができるように |

## レビュー

機能ごとに独立したセキュリティレビューを受け、指摘をすべて直して回帰テストを足した。
ブロック 6 件、メンション 2 件、メール通知 2 件。

## 未対応（次の候補）

- グループのお知らせメール（新しい投稿）は送っていない（通知が多くなりすぎるため、様子を見て判断）
- メールの送信を、Cron とは別のキュー（Vercel Queues など）に分ける（会員が数百人を超えたら）
